
# Working with the Windows Event Log

---

## Overview

The **Windows Event Log** is a centralized logging system that records important events generated by Windows, applications, services, and other system components.

Event logs are essential for system administrators, SOC analysts, and penetration testers because they provide information about system activity, authentication attempts, errors, and potentially suspicious behavior.

In this section, we will learn how to:

- Understand Windows events and event logging.
- Identify different log categories, event types, and severity levels.
- Understand the information contained in an event record.
- Query and export logs using `wevtutil`.
- Search and filter events using the PowerShell `Get-WinEvent` cmdlet.

---

## 1. What Is the Windows Event Log?

An **event** is an identifiable occurrence generated by the operating system, hardware, an application, or a user interaction.

Examples include:

- A user logging in to a computer.
- An application crashing.
- A Windows service failing to start.
- A device driver loading.
- A system update being installed.
- An unsuccessful authentication attempt.

Not every action is necessarily recorded. The events available depend on the logging mechanisms and audit policies configured on the system.

### Event Logging

Event logging provides a standardized way for Windows and applications to record important system activities.

Instead of each application maintaining completely separate logging mechanisms, Windows provides a centralized service called **Windows Event Log**.

From a defensive perspective, these records allow us to investigate incidents, detect suspicious activity, and troubleshoot system problems.

During an authorized penetration test, event logs can also reveal information about the environment and its logging configuration.

---

## 2. Windows Event Log Categories

Windows organizes events into several categories.

| Category | Description |
|---|---|
| `System` | Events related to Windows components, drivers, and system services. |
| `Security` | Security-related events, including successful and failed authentication attempts. |
| `Application` | Events generated by installed applications and software. |
| `Setup` | Events associated with Windows installation and configuration. |
| `Forwarded Events` | Events collected from other computers on the network. |

### System

The System log records events associated with the operating system.

For example, a Windows service that fails during startup may generate an event in this log.

### Security

The Security log records security-related events when the corresponding audit policies are configured.

Examples include successful logons, failed authentication attempts, and privileged account activity.

This is particularly important for SOC analysts investigating unauthorized access.

### Application

The Application log contains events produced by applications.

For example, an application that crashes or encounters an error may record information in this log.

### Setup

The Setup log records events associated with Windows installation and configuration.

### Forwarded Events

Forwarded Events contain records collected from other Windows hosts.

Centralized collection allows administrators to investigate activity across multiple machines without accessing each computer individually.

---

## 3. Event Types

The HTB module introduces five common event types.

| Event type | Description |
|---|---|
| `Error` | Indicates a significant problem, such as a service failing to start. |
| `Warning` | Indicates a potential problem that may require attention. |
| `Information` | Records normal or successful system and application operations. |
| `Success Audit` | Records successful security operations that are being audited. |
| `Failure Audit` | Records unsuccessful security operations that are being audited. |

For example, a successful logon may generate a Success Audit event, while an unsuccessful authentication attempt may generate a Failure Audit event.

Repeated authentication failures can provide evidence for investigating possible password spraying or brute-force activity.

---

## 4. Event Severity Levels

Windows events can have different severity levels.

| Level | Number | Description |
|---|---|---|
| `Critical` | 1 | A serious problem requiring urgent attention. |
| `Error` | 2 | An error affecting a system component or application. |
| `Warning` | 3 | A potential problem that may require investigation. |
| `Information` | 4 | An informational record of system activity. |
| `Verbose` | 5 | Detailed diagnostic or progress information. |

These numerical levels are particularly useful when filtering events using PowerShell.

For example, we can use `Level=1` to search for critical events.

---

## 5. Understanding an Event Record

Each event record contains information that helps us understand what happened, when it happened, and which component generated it.

| Field | Description |
|---|---|
| `Log Name` | The log containing the event, such as Security or System. |
| `Date/Time` | When the event occurred. |
| `Task Category` | The activity category associated with the event. |
| `Event ID` | A numerical identifier for the recorded event. |
| `Source` | The application or Windows component that generated the event. |
| `Level` | The event's severity level. |
| `User` | The account associated with the event, when available. |
| `Computer` | The computer that generated the event. |

### Important Event IDs

The HTB module introduces several security-related Event IDs.

| Event ID | Description |
|---|---|
| `4624` | An account successfully logged on. |
| `4625` | An account failed to log on. |
| `4672` | Special privileges were assigned to a new logon. |
| `4799` | Membership of a security-enabled local group was enumerated. |

These identifiers help us focus on specific activities instead of manually examining every event.

For example, Event ID `4625` is useful when investigating unsuccessful authentication attempts.

## 6. Windows Event Log Technical Details

The Windows Event Log is managed by the `EventLog` service.

This service runs within `svchost.exe` and is normally configured to start automatically.

Windows stores event log files in the following directory by default:

```text
C:\Windows\System32\winevt\Logs
```

The files use the `.evtx` extension.

We can inspect the directory using PowerShell:

```powershell
Get-ChildItem C:\Windows\System32\winevt\Logs
```

Common files include:

```text
Application.evtx
Security.evtx
System.evtx
```

Some event logs contain sensitive information and require elevated permissions to access.

Windows provides several ways to interact with these logs, including the graphical Event Viewer, `wevtutil`, and PowerShell's `Get-WinEvent` cmdlet.

## 7. Working with Event Logs Using Wevtutil

`wevtutil` is a native Windows command-line utility for querying and managing event logs.

It can be used from either CMD or PowerShell.

To display its available commands:

```cmd
wevtutil /?
```

### Common Wevtutil Commands

| Command | Description |
|---|---|
| `wevtutil el` | Lists the available event logs. |
| `wevtutil gl` | Displays a log's configuration. |
| `wevtutil gli` | Displays status and file information for a log. |
| `wevtutil qe` | Queries events. |
| `wevtutil epl` | Exports an event log. |
| `wevtutil cl` | Clears a log. |

### Enumerating Event Logs

We can list the available logs using:

```cmd
wevtutil el
```

Example results:

```text
Application
Security
System
Windows PowerShell
ForwardedEvents
```

### Inspecting Log Configuration

The `gl` parameter retrieves configuration information for a particular log.

For example:

```cmd
wevtutil gl "Windows PowerShell"
```

This can reveal whether logging is enabled, the log's maximum size, its file location, and its access configuration.

### Inspecting Log Status

The `gli` parameter retrieves information about the log file and its existing records.

```cmd
wevtutil gli "Windows PowerShell"
```

Example output:

```text
creationTime: 2020-10-06T16:57:38.617Z
lastWriteTime: 2022-10-26T19:05:21.533Z
fileSize: 11603968
numberOfLogRecords: 9496
oldestRecordNumber: 1
```

**Difference:** `gl` focuses on log configuration, while `gli` provides information about the log's current status and records.

---

## 8. Querying Events with Wevtutil

The `qe` parameter allows us to retrieve events from a specified log.

For example, we can retrieve the five most recent events from the Security log:

```cmd
wevtutil qe Security /c:5 /rd:true /f:text
```

### Understanding the Parameters

| Parameter | Description |
|---|---|
| `qe Security` | Queries the Security log. |
| `/c:5` | Limits the output to five events. |
| `/rd:true` | Displays the newest events first. |
| `/f:text` | Formats the output as readable text. |

The returned events include their Event IDs, timestamps, sources, severity levels, and descriptions.

### Exporting Event Logs

We can export an event log for offline analysis using `epl`.

For example:

```cmd
wevtutil epl System C:\system_export.evtx
```

This exports the System log to an `.evtx` file.

Exported logs can be transferred to an authorized analysis environment for further investigation.

**Security consideration:** Reading certain logs and exporting protected event records may require administrative privileges.

## 9. Working with Event Logs Using PowerShell

PowerShell provides the `Get-WinEvent` cmdlet for querying event logs.

Its structured output allows us to filter events by properties such as Event ID, severity level, and timestamp.

### Listing Available Logs

We can enumerate all available event logs using:

```powershell
Get-WinEvent -ListLog *
```

The output includes information such as:

- Log name.
- Maximum log size.
- Number of records.
- Log retention mode.

### Inspecting a Specific Log

To retrieve information about the Security log:

```powershell
Get-WinEvent -ListLog Security
```

This allows us to inspect the log without retrieving every event stored within it.

---

## 10. Querying Events with Get-WinEvent

### Retrieving Recent Events

We can retrieve the five most recent events from the Security log using:

```powershell
Get-WinEvent -LogName 'Security' -MaxEvents 5
```

The `-MaxEvents` parameter limits the number of returned records.

By default, `Get-WinEvent` retrieves the newest events first.

We can use `-Oldest` when we need to process records in chronological order, beginning with the oldest event.

### Displaying Event Messages

If we only want to inspect the descriptions of the retrieved events, we can combine `Get-WinEvent` with `Select-Object`:

```powershell
Get-WinEvent -LogName 'Security' -MaxEvents 5 |
    Select-Object -ExpandProperty Message
```

The `Message` property contains the descriptive information associated with an event.

This demonstrates how PowerShell's object-based pipeline helps us retrieve specific information without displaying every available property.

---

## 11. Filtering Events by Event ID

We can use `Get-WinEvent` with `-FilterHashtable` to retrieve records matching particular conditions.

For example, Event ID `4625` represents a failed logon attempt.

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    ID = 4625
}
```

This retrieves matching events from the Security log.

Example output:

```text
TimeCreated              Id    Message
-----------              --    -------
11/16/2022 2:53:16 PM    4625  An account failed to log on.
11/16/2022 2:53:12 PM    4625  An account failed to log on.
```

Filtering directly by Event ID is useful when investigating specific types of security activity.

### Why Use FilterHashtable?

Instead of retrieving every event and filtering the results afterward, `-FilterHashtable` allows us to define conditions as part of the event log query.

This is particularly useful when searching large logs containing thousands of records.

---

## 12. Filtering Events by Severity

We can also retrieve events based on their severity levels.

For example, to identify critical events from the System log:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'System'
    Level = 1
}
```

The value `1` corresponds to the Critical severity level.

We can display only the associated event messages using:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'System'
    Level = 1
} | Select-Object -ExpandProperty Message
```

In the HTB example, this query identifies an event indicating that Windows restarted without shutting down properly.

## 13. Why Event Logs Matter in Cybersecurity

Windows Event Logs provide valuable information for both offensive and defensive security assessments.

### Defensive Applications

SOC analysts and system administrators use logs to:

- Investigate successful and failed authentication attempts.
- Identify unexpected service or system behavior.
- Troubleshoot application failures.
- Investigate unexpected reboots.
- Correlate suspicious activity across multiple systems.

### Penetration Testing

During an authorized penetration test, we can use event logs to understand the environment and determine which activities are being monitored.

The presence or absence of particular records may provide information about the organization's audit configuration.

### Centralized Logging and SIEM

Manually reviewing thousands of event records across hundreds of computers is inefficient.

Organizations commonly forward logs to a **Security Information and Event Management (SIEM)** platform.

A SIEM helps security teams centralize event collection, correlate activity, and create alerts for suspicious patterns.

For example, repeated Event ID `4625` records associated with multiple accounts may warrant investigation for password spraying.

## Key Takeaways

- Windows Event Log provides centralized recording of important system, application, and security events.
- Its principal log categories include System, Security, Application, Setup, and Forwarded Events.
- Event records contain fields such as Event ID, timestamp, source, severity, and computer name.
- Windows stores event logs in `.evtx` files, commonly under `C:\Windows\System32\winevt\Logs`.
- `wevtutil` allows us to enumerate, query, inspect, and export event logs from the command line.
- `Get-WinEvent` provides structured event log queries through PowerShell.
- Event ID `4624` represents a successful logon, while `4625` represents a failed logon.
- `-FilterHashtable` allows us to efficiently retrieve events matching specific criteria.
- Centralized log collection and SIEM platforms make event monitoring more effective across enterprise environments.
