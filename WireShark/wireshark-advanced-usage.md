
# Wireshark Advanced Usage

## Introduction

Wireshark provides advanced network traffic analysis capabilities beyond basic packet capturing and filtering.

These features allow analysts to:

- Examine network statistics.
- Identify conversations between hosts.
- Follow TCP streams.
- Reconstruct network communications.
- Extract files from packet captures.
- Analyze protocol-specific information.

Wireshark includes several built-in tools and plugins accessible through its menus.

---

## Statistics and Analyze Tabs

The **Statistics** and **Analyze** tabs provide additional capabilities for examining captured traffic.

### Statistics Tab

The Statistics tab provides reports about the network traffic contained in a capture.

It can help identify:

- Top talkers in the network.
- Network conversations.
- IP addresses involved in communications.
- Protocol distribution.
- Traffic statistics.

These reports help analysts understand communication patterns within the captured network traffic.

### Analyze Tab

The Analyze tab provides tools for examining packets and conversations in greater detail.

Examples include:

- Following TCP streams.
- Filtering network conversations.
- Preparing and applying packet filters.
- Examining expert information generated by Wireshark.

These capabilities help analysts investigate specific communications without manually reviewing every packet.

## Following TCP Streams

Wireshark can reconstruct TCP streams by combining data from packets belonging to the same TCP conversation.

This functionality is called **Follow TCP Stream**.

A TCP conversation may contain many individual packets, each carrying part of the transmitted data.

Instead of examining the packets separately, Wireshark can reassemble their contents into a readable stream.

### Why Follow TCP Streams?

This feature allows analysts to:

- Examine an entire TCP conversation.
- Identify data exchanged between a client and server.
- Reconstruct application-level communications.
- Investigate transferred content.
- Focus on packets belonging to a specific connection.

### Following a TCP Stream Through the GUI

1. Open a PCAP file in Wireshark.
2. Select a packet belonging to the desired TCP conversation.
3. Right-click the packet.
4. Select **Follow → TCP Stream**.
5. Examine the reconstructed communication.

Wireshark opens a window containing the stream data.

### Filtering a Specific TCP Stream

Wireshark also provides a display filter for individual TCP streams.

```text
tcp.stream eq 0
```

This displays packets associated with TCP stream number `0`.

The stream number identifies a particular TCP conversation within the capture.

### Example

```text
tcp.stream eq 1
```

This displays packets belonging to TCP stream number `1`.

### TCP Stream Analysis

A TCP conversation normally begins with the Three-way Handshake:

```text
SYN
SYN, ACK
ACK
```

After the handshake, the endpoints exchange application data.

Filtering the corresponding TCP stream allows us to examine this communication without unrelated packets appearing in the Packet List.

**Important:** Following a TCP stream reconstructs the captured data belonging to that conversation. It does not automatically decrypt encrypted application traffic.

## Extracting Data and Files From a Capture

Wireshark can recover certain files and other data transferred over network connections.

Examples of supported protocol-related export capabilities discussed in the HTB material include:

- HTTP
- SMB
- DICOM

### File Extraction

Wireshark can reconstruct transferred content from captured network packets.

To successfully reconstruct a file, the capture must contain the necessary data from the transfer.

If important packets are missing, the reconstructed content may be incomplete.

### Extracting Files Through the GUI

1. Stop the packet capture.
2. Open the **File** menu.
3. Locate the export functionality for protocol objects.
4. Select the applicable protocol.
5. Export the desired content.

The available export options depend on the protocol and the data present in the capture.

### Important Consideration

File reconstruction depends on having sufficient captured traffic.

An incomplete capture may prevent successful extraction.

## Extracting Files From FTP Traffic

FTP (File Transfer Protocol) is used to transfer files between clients and servers.

FTP uses TCP as its transport protocol.

The HTB material examines how FTP traffic can be identified and how transferred files can be reconstructed from a PCAP.

### FTP Connections

FTP separates commands and file transfers into different communication channels.

| Channel | Traditional Port | Purpose |
|---|---|---|
| Control | TCP 21 | Commands, authentication, and transfer requests |
| Data | TCP 20 | File transfers in traditional active FTP |

The control channel is used for operations such as:

- User authentication.
- Directory listing.
- Changing directories.
- Requesting file downloads.
- Requesting file uploads.

The data channel carries the transferred file contents.

### FTP Display Filters

The HTB section focuses on three Wireshark display filters:

```text
ftp
ftp.request.command
ftp-data
```

Each filter helps investigate a different part of FTP communication.

---

## FTP Filter

### Filter

```text
ftp
```

This displays packets recognized as FTP protocol traffic.

### Purpose

The filter can help identify:

- FTP clients.
- FTP servers.
- FTP control communications.
- Hosts involved in FTP sessions.

It provides an initial overview of the FTP activity present in the capture.

---

## FTP Request Command Filter

### Filter

```text
ftp.request.command
```

This displays packets containing FTP request commands.

These commands are transmitted through the FTP control channel.

### Purpose

This filter can help identify:

- Authentication commands.
- Directory navigation.
- File listing requests.
- File download requests.
- File upload requests.
- Filenames associated with transfer requests.

### Example FTP Commands

```text
USER anonymous
PASS password
LIST
RETR secrets.txt
```

The HTB material highlights that FTP control traffic can reveal sensitive information, including usernames, passwords, and requested filenames.

Because traditional FTP does not encrypt its control channel, this information may be visible in plaintext captures.

---

## FTP Data Filter

### Filter

```text
ftp-data
```

This displays FTP data transfer traffic recognized by Wireshark.

### Purpose

The filter allows analysts to locate packets containing transferred data.

This can help identify the stream associated with a file transfer and reconstruct its contents.

### Example

Suppose an FTP client requests:

```text
RETR secrets.txt
```

The control connection contains the request, while the data connection carries the contents of the file.

The corresponding FTP data stream can be followed and its raw contents saved.

## Reconstructing an FTP File

The HTB material provides the following process for extracting a file from FTP traffic.

### Step 1 - Identify FTP Traffic

Apply the display filter:

```text
ftp
```

Examine the communication between the FTP client and server.

### Step 2 - Identify FTP Commands

Apply:

```text
ftp.request.command
```

Look for commands associated with file transfers.

Determine:

- Which host requested the file.
- Which server responded.
- Which filename was requested.

### Step 3 - Locate the Data Transfer

Apply:

```text
ftp-data
```

Identify the packets corresponding to the desired file transfer.

### Step 4 - Follow the TCP Stream

Select a packet belonging to the file transfer.

Right-click and select:

**Follow → TCP Stream**

Wireshark reconstructs the captured data from the selected TCP conversation.

### Step 5 - Save the Raw Data

In the Follow TCP Stream window, locate the option:

**Show and save data as**

Change the representation to:

```text
Raw
```

Save the data using the original filename.

For example:

```text
secrets.txt
```

### Step 6 - Validate the Extracted File

After saving the reconstructed file, verify that it has the expected file type.

On Linux, this can be checked using:

```bash
file secrets.txt
```

The purpose is to confirm that the saved data corresponds to the expected file format.

### Important Consideration

Successful reconstruction requires that the captured data contains the relevant file transfer.

If the capture is incomplete, the resulting file may also be incomplete.
