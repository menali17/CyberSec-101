# Package Management

Package management is the system Linux uses to **install, update, remove, and manage software**.

A package normally contains more than just the program itself. It can include:

```text id="3h0kfp"
Software binaries
Configuration files
Dependency information
Version information
Installation instructions
```

Package managers also help ensure that software dependencies are installed correctly.

---

# Packages and Dependencies

Many programs depend on other programs or libraries to work.

For example:

```text id="c5vh97"
Program A
   │
   ├── requires Library B
   │
   └── requires Package C
```

Instead of requiring us to manually find and install every dependency, a package manager can resolve them automatically.

Conceptually:

```text id="g7nbaf"
We request a package
        │
        ▼
Package Manager
        │
        ├── Find package
        ├── Check dependencies
        ├── Download dependencies
        ├── Install dependencies
        └── Install package
```

Package management systems commonly provide:

* Package downloading
* Dependency resolution
* Standard package formats
* Standard installation locations
* Configuration functionality
* Update and upgrade management

---

# Common Package Formats

Different Linux distributions use different package formats.

Two common formats are:

```text id="4m4zw3"
.deb
.rpm
```

Debian-based distributions use:

```text id="h1rztm"
.deb
```

packages.

Examples of Debian-based distributions include Debian, Ubuntu, Kali Linux, and Parrot OS.

# APT

`APT` stands for:

```text id="uw2o8e"
Advanced Package Tool
```

It is used by Debian-based Linux distributions.

APT provides a convenient high-level interface for managing software.

One of its major advantages is **dependency management**.

Instead of manually downloading:

```text id="5frlvp"
program.deb
dependency1.deb
dependency2.deb
dependency3.deb
```

APT can resolve the required packages for us.

Conceptually:

```text id="e84p18"
apt install program
       │
       ▼
Check repositories
       │
       ▼
Find program
       │
       ▼
Determine dependencies
       │
       ▼
Download everything
       │
       ▼
Install everything
```

---

# Software Repositories

APT obtains packages from **repositories**.

Repositories are servers containing software packages maintained for a Linux distribution.

Conceptually:

```text id="e5wsgf"
Our Linux System
       │
       │ APT request
       ▼
Software Repository
       │
       ├── Package A
       ├── Package B
       ├── Package C
       └── Package D
```

Repository configuration can be stored in locations such as:

```text id="c97sye"
/etc/apt/sources.list
```

The HTB Parrot OS example uses:

```text id="d0o7cu"
/etc/apt/sources.list.d/parrot.list
```

We can inspect it using:

```bash id="qak2fj"
menali@htb[/htb]$ cat /etc/apt/sources.list.d/parrot.list

# parrot repository
# this file was automatically generated by parrot-mirror-selector
deb http://htb.deb.parrot.sh/parrot/ rolling main contrib non-free
#deb-src https://deb.parrot.sh/parrot/ rolling main contrib non-free
deb http://htb.deb.parrot.sh/parrot/ rolling-security main contrib non-free
#deb-src https://deb.parrot.sh/parrot/ rolling-security main contrib non-free
```

This searches for packages related to:

We can install packages using:

```bash id="qptn7k"
sudo apt install <package>
```

The HTB example installs:

```text id="70w1ga"

```

using:

```bash id="i7hp01"
menali@htb[/htb]$ sudo apt install impacket-scripts -y
```

Output:

```bash id="qlw1cc"

  impacket-scripts

Need to get 2,080 B of archives.
After this operation, 13.3 kB of additional disk space will be used.
<SNIP>
Setting up impacket-scripts (1.4) ...
```

Breaking down:

```text id="17m84d"
sudo
│
└── Execute with elevated privileges

│
└── Package manager

│
```

So:


means:

> Install the `impacket-scripts` package and automatically confirm the installation prompts.

# Git

`git` is not a traditional Linux package manager like APT or DPKG.

It is a **distributed version control system**.

However, in cybersecurity we frequently use Git to obtain tools and projects hosted in Git repositories.

A common command is:

```bash id="un68cy"
git clone <repository>
```

This downloads a copy of a repository.

---

# Cloning a Repository

The HTB example uses the Nishang project.

First, we create a directory:


```bash id="3rj05a"
git clone https://github.com/samratashok/nishang.git ~/nishang
```

# DPKG

`dpkg` is a lower-level tool for managing Debian packages.

It works directly with:

```text id="6n3h2b"

```

files.

The relationship can be simplified as:

```text id="wxwczq"
APT
│
├── Higher-level
├── Uses repositories
└── Handles dependencies more conveniently


DPKG
│
├── Lower-level
└── Works directly with .deb packages
```

# APT vs DPKG

This distinction is important.

### APT

```bash id="y6s6u3"
sudo apt install package
```

APT:

```text id="zvpxlq"
Uses repositories
Finds packages
Handles dependencies
Downloads required packages
Installs them
```

### DPKG

```bash id="b9ogf9"
sudo dpkg -i package.deb
```

DPKG:

```text id="tzd8uq"
Works directly with a .deb file
Installs the local Debian package
```

A useful mental model is:

```text id="p3udms"
APT
↓
"Find and install this software for us."


DPKG
↓
"Install this .deb file we already have."
```

# Different Ways We Can Obtain Software

This section demonstrates three different approaches.

### APT Repository

```bash id="e7z0ge"
sudo apt install package
```

```text id="6vk7mz"
Repository
   ↓
APT
   ↓
Package + dependencies
   ↓
Installed software
```

### Git Repository

```bash id="05v3pj"
git clone <repository>
```

```text id="ygn82i"
Git repository
     ↓
git clone
     ↓
Project files/source code
```

### Standalone `.deb`

```bash id="5ldg78"
wget package.deb
sudo dpkg -i package.deb
```

```text id="ys39mg"
Website/server
     ↓
wget
     ↓
package.deb
     ↓
dpkg -i
     ↓
Installed software
```

These methods are related but are **not the same thing**.

## Key Takeaway

**Linux package management provides standardized ways to install, update, remove, and manage software and its dependencies. On Debian-based systems, APT provides a convenient high-level interface that works with repositories and dependency resolution, while DPKG works directly with `.deb` packages. We can also obtain software through Git repositories with `git clone` or download standalone packages using tools such as `wget`.**
