# HTTP Requests and Responses

HTTP communication consists of:

* **Request** — sent by the client.
* **Response** — returned by the server after processing the request.

This section focuses on the internal structure of these messages.

---

# HTTP Request

Example request:

```http
GET /users/login.html HTTP/1.1
Host: inlanefreight.com
User-Agent: Mozilla/5.0
Cookie: PHPSESSID=c4ggt4jull9obt7aupa55o8vbf
```

## Request Line

The first line contains three fields:

```text
Method Path Version
```

Example:

```http
GET /users/login.html HTTP/1.1
```

| Field       | Example             | Description        |
| ----------- | ------------------- | ------------------ |
| **Method**  | `GET`               | Action to perform  |
| **Path**    | `/users/login.html` | Requested resource |
| **Version** | `HTTP/1.1`          | HTTP version       |

The path may also contain a query string:

```text
/users/login.html?username=user
```

## Request Headers

Headers provide additional information about the request:

```http
Host: inlanefreight.com
User-Agent: Mozilla/5.0
Cookie: PHPSESSID=c4ggt4jull9obt7aupa55o8vbf
```

They follow the format:

```text
Header-Name: Value
```

Headers are followed by an empty line. A request may then contain a **request body** with data sent to the server.

---

# HTTP Response

After processing the request, the server returns an HTTP response.

Example:

```http
HTTP/1.1 200 OK
Server: Apache/2.4.41
Content-Type: text/html; charset=UTF-8

<html>
...
</html>
```

## Status Line

The first line contains:

```text
HTTP Version + Status
```

Example:

```http
HTTP/1.1 200 OK
```

The status code indicates the result of the request.

## Response Headers

The server can return headers such as:

```http
Date: Tue, 21 Jul 2020 05:20:15 GMT
Server: Apache/2.4.41
Content-Length: 464
Content-Type: text/html; charset=UTF-8
```

## Response Body

After an empty line, the response may contain a body.

The body can contain:

* HTML
* JSON
* CSS
* JavaScript
* Images
* Documents
* Other resource types

---

# HTTP/1.x vs. HTTP/2

The material introduces one structural difference:

| HTTP/1.x                         | HTTP/2                |
| -------------------------------- | --------------------- |
| Text-based representation        | Binary representation |
| Fields separated using new lines | Binary framing        |

# Inspecting HTTP with cURL

The `-v` flag displays detailed request and response information:

```bash
menali@htb[/htb]$ curl inlanefreight.com -v
```

Example:

```bash
*   Trying SERVER_IP:80...
* Connected to inlanefreight.com (SERVER_IP) port 80 (#0)
> GET / HTTP/1.1
> Host: inlanefreight.com
> User-Agent: curl/7.65.3
> Accept: */*
> Connection: close
>
< HTTP/1.1 401 Unauthorized
< Date: Tue, 21 Jul 2020 05:20:15 GMT
< Server: Apache/X.Y.ZZ (Ubuntu)
< WWW-Authenticate: Basic realm="Restricted Content"
< Content-Length: 464
< Content-Type: text/html; charset=iso-8859-1
<
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">
<html><head>
...SNIP...
```

The prefixes make the output easy to interpret:

| Prefix | Meaning                                |
| ------ | -------------------------------------- |
| `>`    | HTTP request sent by cURL              |
| `<`    | HTTP response received from the server |
| `*`    | cURL connection/debug information      |

For example:

```bash
> GET / HTTP/1.1
```

is part of the request, while:

```bash
< HTTP/1.1 401 Unauthorized
```

is part of the response.

`401 Unauthorized` indicates that authentication is required for the requested resource.

For additional verbosity:

```bash
curl -vvv inlanefreight.com
```

# Browser DevTools

Browser **Developer Tools (DevTools)** also allow us to inspect HTTP traffic generated by a web application.

Open DevTools with:

```text
Ctrl + Shift + I
```

or:

```text
F12
```

For HTTP analysis, the main section is the **Network** tab.

After refreshing the page, it displays requests generated by the browser and information such as:

* Request method
* URL and path
* Response status
* Individual request and response details

The filtering functionality can be used to locate specific requests when an application generates many of them.

# Quick Reference

### Request

```http
METHOD /path HTTP/version
Headers

Optional Body
```

### Response

```http
HTTP/version STATUS
Headers

Optional Body
```

### Inspect with cURL

```bash
curl -v <URL>
```

```text
> → Request
< → Response
* → cURL information
```

### Browser

```text
F12 → Network
```

---

## Key Takeaway

**An HTTP request contains a request line, headers, and optionally a body. An HTTP response contains a status line, headers, and optionally a body. `curl -v` and the browser DevTools Network tab allow us to inspect these messages directly.**
