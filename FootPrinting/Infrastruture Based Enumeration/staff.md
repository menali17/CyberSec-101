# Staff

---

## Overview

Employees and job postings can reveal valuable information about an organization's infrastructure and technology stack.

During passive reconnaissance, we can analyze publicly available professional information to identify technologies, frameworks, tools, and security practices.

Common sources include:
- LinkedIn
- Xing
- Job postings
- Public GitHub repositories

---

## Job Postings

Job descriptions can provide insights into technologies potentially used by an organization.

We may discover:

- Programming languages (Python, Java, C#)
- Databases (PostgreSQL, MySQL, Oracle)
- Web frameworks (Django, Flask, Spring)
- Development tools (Git, Jira, Bitbucket)
- Infrastructure technologies (Docker, Kubernetes)

These technologies provide clues about the company's infrastructure, but their presence in a job posting does not confirm they are actively deployed.

---

## Employee Profiles

Professional profiles may reveal:

- Technical skills
- Previous projects
- Development frameworks
- Security technologies
- Areas of responsibility

We can use this information to understand the organization's potential technology stack and security practices.

---

## GitHub and Information Exposure

Public repositories may unintentionally expose sensitive information.

Examples include:

- Email addresses
- Hardcoded credentials
- API keys
- JWT tokens
- Application configuration details

Exposed credentials or tokens may represent security risks if they are valid and provide unauthorized access.

We should investigate publicly available technical information within the authorized scope of our assessment.

---

## Key Takeaways

- Employees and job postings are valuable OSINT sources.
- Public professional information can reveal technologies used by an organization.
- GitHub repositories may expose sensitive information through insecure development practices.
- Technical skills and job requirements provide clues, not definitive proof of deployed technologies.
- Staff reconnaissance helps us identify areas for further technical investigation.

**Our goal is to understand the organization's technical environment using publicly available information.**
